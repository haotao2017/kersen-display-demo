# Kersen ESL Cloud 用户使用说明

本文档面向门店运营人员、系统管理员和现场实施人员，说明如何使用 Kersen ESL Cloud 完成电子价签系统的日常操作，包括账号登录、门店配置、基站接入、标签上线、数据源维护、模板设计、任务下发和常见问题排查。

## 1. 系统概念

Kersen ESL Cloud 是一套电子价签管理系统，主要由以下几类数据组成：

- 门店：基站和标签所属的业务门店。基站配置里的门店号必须先在系统中创建。
- AP 基站：也叫 eStation / AP Station，用于连接标签、扫描标签并接收系统下发的刷新命令。
- 显示节点：系统里的电子价签记录，通常对应一个标签码，例如 `14376dec`。
- 数据源：系统里的商品或业务数据。页面上叫“商品管理”或“Data Source”，用于给模板提供字段内容。
- 模板：价签画面设计。模板决定标签上显示哪些文本、价格、图片、二维码、条码和图形。
- 任务：系统向标签下发刷新时生成的记录。任务中心可以查看排队、发送、成功、失败和重试情况。

推荐使用顺序：

1. 创建账号和门店。
2. 登记 AP 基站。
3. 配置真实基站连接到本系统。
4. 打开基站自动扫描入库，让标签自动进入显示节点列表。
5. 创建数据源。
6. 创建模板并发布。
7. 将显示节点绑定到数据源和模板。
8. 下发刷新任务并在任务中心查看结果。

## 2. 登录与账号

默认本地/初始账号：

- 用户名：`admin`
- 密码：`admin123456`

生产环境请在首次部署后尽快修改密码，并设置强 `JWT_SECRET`。

系统角色：

- ADMIN：管理员。可以查看自己和非管理员账号的数据，可以管理用户、邀请、门店、基站、模板、数据源和任务。
- OPERATOR：操作员。只能看到自己权限下的数据，可以进行门店日常操作。
- VIEWER：查看者。适合只查看状态和任务结果的人员。

创建新账号：

1. 登录管理员账号。
2. 进入“系统设置”。
3. 在“创建受控注册邀请”里填写用户名、显示名称、邮箱、角色和默认门店。
4. 点击“创建邀请并复制注册链接”。
5. 将注册链接发给用户，用户通过该链接设置密码并完成注册。

账号注意事项：

- 邀请链接有有效期，默认可设置 1 到 30 天。
- 已使用或已撤销的邀请不能再次注册。
- 管理员可以在“用户列表”中禁用、启用用户，也可以重置密码。
- 重置密码后，该用户原有登录会话会失效。

## 3. 门店配置

进入“门店管理”页面。

新增门店：

1. 点击“新增门店”。
2. 填写门店名称。
3. 填写门店号。门店号只能是数字，例如 `20248517`。
4. 管理员可以选择归属账号。
5. 可选填写门店地址。
6. 点击保存。

门店号非常重要：

- 基站连接系统时会携带门店号。
- 如果基站上配置的门店号在系统中不存在，基站不会正确登记，也不会显示在基站列表。
- 基站、标签、数据源和模板都会通过门店号归属到对应门店。

删除门店：

- 删除门店会删除该门店下的基站记录。
- 标签、模板、商品数据本身会保留，但会解除它们与该门店或基站的关联。
- 删除前请确认该门店不再使用。

## 4. AP 基站登记

进入“AP 基站”页面。

新增基站：

1. 点击“新增基站”。
2. 选择所属门店。
3. 填写 AP 编码。可以不填，不填时系统会自动生成。
4. 填写基站名称，例如“一楼生鲜区基站”。
5. 填写 IP 地址、MAC 地址、固件版本和安装位置。
6. 心跳间隔建议不低于 15 秒。
7. 信道、发射功率按现场基站要求填写。
8. 点击“保存基站”。

AP 编码和 MAC 的关系：

- 如果已知道基站 MAC，建议填写 MAC 地址。
- 系统会用 MAC 识别同一个真实基站，避免重复创建。
- 真实基站认证后，如果系统能匹配到已登记 MAC，会把连接归到对应 AP。

基站列表字段说明：

- Owner：管理员视角下显示数据归属账号。
- 所属门店：显示门店名称和门店号。
- AP 编码：基站唯一编码。
- 状态：在线或离线。
- 已绑定显示节点数：已经绑定到商品或模板的正式标签数量。
- 自动发现显示节点数：基站扫描到的标签数量。
- 入库开/入库关：控制扫描到的新标签是否自动写入显示节点列表。

## 5. 真实基站如何连接系统

真实基站需要在基站设备配置页面中填写服务器和门店认证信息。不同固件界面名称可能略有不同，一般在 `ESL -> AP Config` 或类似页面。

建议填写：

- 服务器地址：本系统 API 地址，例如 `http://服务器IP:4000` 或 `https://api.example.com`
- 门店编号：系统“门店管理”里创建的门店号，例如 `20248517`
- 用户名：该门店的基站认证用户名，默认通常是 `admin`
- 密码：该门店的基站认证密码，默认初始为 `admin123456`

重要提醒：

- 真实基站不能填写 `localhost`。`localhost` 在基站上表示基站自己，不是服务器。
- 如果系统部署在云服务器，基站必须能访问云服务器公网地址和端口。
- 如果系统部署在局域网电脑，基站必须和服务器在同一网络，并填写服务器局域网 IP。
- 默认基站 WebSocket 连接路径为 `/ws`。
- 基站认证接口为 `/api/websocket/auth`，认证成功后会获得 token，再连接 WebSocket。
- MQTT 默认 TCP 端口是 `1883`，但当前真实下发主要通过 AP WebSocket 完成，MQTT 更多用于桥接和观察。

判断基站是否连接成功：

1. 进入“AP 基站”页面。
2. 找到对应 AP。
3. 状态显示“在线”。
4. 进入基站详情，查看“最后心跳”和“最近心跳”是否持续更新。
5. “基站接入 / 下发日志”中可以看到基站连接、心跳、扫描和下发相关记录。

如果基站不在线：

- 检查服务器地址是否能被基站访问。
- 检查门店号是否已在系统中创建。
- 检查用户名和密码是否正确。
- 检查防火墙或安全组是否放通 API 端口，默认是 `4000`。
- 检查基站时间、网络和 DNS。
- 云服务器环境下，不要只开放 Web 端口，也要开放 API 端口。

## 6. 让基站扫描标签并自动入库

标签上线的核心条件：

- 基站在线。
- 标签在基站有效通信范围内。
- 标签电池正常。
- 基站能扫描到标签上报，例如 `DEVICE_RETRIEVE` 或 `SLAVE_ADV_SVC`。
- 对应 AP 开启“自动扫描入库”。

开启自动扫描入库：

1. 进入“AP 基站”页面。
2. 找到对应基站。
3. 点击“入库关”开关。
4. 阅读确认弹窗。
5. 点击“确认开启”。

开启后系统行为：

- 基站上报扫描结果时，新发现标签会自动进入“显示节点”列表。
- 已存在标签会更新在线状态、信号和服务信息。
- 标签会绑定到扫描到它的基站。
- 基站详情中“自动发现设备”会显示扫描缓存。

关闭后系统行为：

- 基站仍会保留自动发现记录。
- 不会自动新增正式显示节点。
- 已有显示节点不会因为关闭开关而删除。

现场让标签上线的建议步骤：

1. 确认基站在线。
2. 将标签放在基站通信范围内。
3. 等待基站扫描周期完成。标签较多时可能需要数分钟。
4. 在“AP 基站”详情里查看“自动发现设备”数量是否增加。
5. 在“显示节点”列表搜索标签码，确认是否已入库。
6. 如果标签仍未出现，点击显示节点里的“唤醒”，或等待下一轮扫描。

标签状态说明：

- online：系统最近确认标签在线或收到标签扫描上报。
- offline：超过在线稳定窗口后仍未确认在线。
- updating：标签正在刷新。
- failed：最近刷新失败。
- idle：初始或未明确状态。

基站刚上线时的注意事项：

- 基站刚上线会有一段扫描和唤醒过程，标签数量多时不要立即连续触发大量刷新。
- 系统会优先处理刷新任务，基站空闲后再处理标签在线状态探测。
- 已确认在线的标签短时间内不会反复扫描确认，避免在线数量剧烈波动。
- 若某个标签没有返回，任务会进入待触发或失败状态，可稍后重试。

## 7. 显示节点管理

进入“显示节点”页面。

常用筛选：

- 按门店筛选。
- 按基站筛选。
- 管理员可按用户筛选。
- 按标签码或设备名称搜索。

手动添加节点：

1. 点击“手动添加节点”。
2. 填写设备名称。
3. 填写显示节点码，也就是标签码。
4. 可选选择所属 AP。
5. 点击确认。

编辑节点：

1. 点击某一行“编辑”。
2. 可以修改设备名称、显示节点码、所属 AP、数据源和模板。
3. 点击确认保存。

绑定单个节点：

1. 找到未绑定标签。
2. 点击“绑定”。
3. 选择数据源。
4. 可选选择模板。
5. 点击确认。

批量绑定：

1. 在表格中勾选多个显示节点。
2. 点击“批量绑定”。
3. 可以只选数据源、只选模板，或两者同时选择。
4. 点击确认。

解绑：

- 单个标签点击“解绑”。
- 多个标签勾选后点击“批量解绑”。
- 解绑只解除显示节点与数据源/模板的关系，不删除标签。

刷新：

- 标签已绑定数据源和模板后，可以点击“刷新”。
- 刷新会创建任务，任务会进入任务中心排队执行。
- 如果标签没有可用模板，刷新不会生成有效任务。

唤醒：

- 点击“唤醒”可以让系统尝试通过基站唤醒或确认该标签。
- 标签离线、刚上架或刚更换电池时可以先尝试唤醒。

删除显示节点：

- 删除只删除系统里的显示节点记录。
- 不会删除商品、模板或基站。
- 会解除相关任务、商品、模板、基站关联。

## 8. 数据源/商品管理

进入“商品管理”页面。系统里“商品”也叫“数据源”，它为模板提供动态字段。

新增数据源：

1. 点击“新增商品”。
2. 默认只显示必要字段。
3. 填写名称 `#name`。
4. 填写来源编号 `#sourceId`，通常可填 SKU 或业务编号。
5. 设置状态，常用 `active`。
6. 可点击“添加字段”显示更多字段。
7. 可选择默认模板。
8. 点击“保存数据源”。

常用字段对应关系：

- 名称：`#name`
- 来源编号：`#sourceId`
- 参考值：`#reference`
- 字段 1：`#field1`
- 字段 2：`#field2`
- 副标题：`#subName`
- 规格：`#specification`
- 单位：`#unit`
- 会员价：`#memberPrice`
- 原价：`#originalPrice`
- 促销文案：`#promotionText`
- 品牌 / 厂商：`#brand`
- 商品图片：`#imageUrl`
- 自定义字段 1：`#customField1`
- 自定义字段 2：`#customField2`
- 依此类推，最多到 `#customField22`

上传商品图片：

1. 在商品详情里添加“商品图片”字段。
2. 点击“上传图片”。
3. 选择本地图片。
4. 保存后，模板中的图片元素会优先使用商品图片。

编辑数据源：

- 修改数据源保存后，如果该数据源绑定了很多标签，系统会为相关标签创建刷新任务。
- 标签很多时，任务会排队慢慢执行，不需要一直停留在当前页面。
- 可到“任务中心”查看执行进度。

触发刷新：

1. 在商品列表点击“触发刷新”。
2. 系统会查找绑定该数据源的显示节点。
3. 对有可用模板的标签创建刷新任务。
4. 如果没有绑定节点或没有模板，系统会提示原因。

## 9. 模板管理

模板决定最终标签屏幕显示效果。

新增模板：

1. 进入“模板管理”。
2. 点击“新增模板”。
3. 填写模板名称。
4. 填写模板编码。
5. 选择屏幕规格。
6. 选择色彩模式。
7. 管理员可选择归属账号。
8. 点击“保存模板”，系统会进入模板设计器。

屏幕规格：

- 必须选择与真实标签尺寸匹配的规格。
- 系统会按模板尺寸渲染图片，如果尺寸不匹配，标签显示可能拉伸、裁剪或刷新失败。
- 143 系列标签应选择对应的 143 系列规格。

色彩模式：

- 2 色：通常为黑白。
- 3 色：通常为黑白红，系统默认更推荐用于 143 系列三色标签。
- 4 色：用于支持更多颜色的屏幕。

选择色彩模式的原则：

- 标签硬件支持几色，就选择几色。
- 模板颜色应尽量使用系统颜色面板里的颜色。
- 三色标签不要依赖复杂渐变和半透明效果，实际渲染会被转成标签可显示的有限颜色。

模板列表操作：

- 设计：进入模板设计器。
- 发布：保存并发布模板，同时为绑定该模板的标签创建刷新任务。
- 删除：删除模板并解除标签或数据源默认模板关联，不删除标签、商品或任务记录。

## 10. 模板设计器详细说明

模板设计器分为三部分：

- 左侧：元素、颜色、模板缩略图和帮助面板。
- 中间：画布，显示实际标签布局。
- 右侧：模板信息和选中元素属性。

顶部工具：

- 撤销：撤销上一步编辑。
- 重做：恢复撤销的编辑。
- 复制：复制选中元素。
- 删除：删除选中元素。
- 缩放：调整画布查看比例。
- 发布：保存模板并发布，可能创建标签刷新任务。
- 保存：仅保存模板，不一定下发到标签。

添加元素：

1. 左侧选择“元素”。
2. 点击文本、价格、标签、图片、条码、二维码、矩形或线条。
3. 元素会出现在画布中。
4. 拖动元素调整位置。
5. 选中元素后在右侧精确设置 X、Y、宽、高、字体、颜色等。

元素类型：

- 文本：普通文字，可绑定商品字段。
- 价格：适合显示价格数字，也可绑定字段。
- 标签：适合显示短标签、单位、促销标识。
- 图片：设计时可上传预览图，实际渲染优先使用商品图片。
- 条码：根据绑定内容生成条码。
- 二维码：根据绑定内容生成二维码。
- 矩形：用于背景块、边框或分区。
- 线条：用于分割线。

绑定字段：

1. 选中可绑定元素，例如文本、价格、标签、条码或二维码。
2. 在右侧“绑定字段”选择字段。
3. 可在“示例内容”填写设计时预览文本。
4. 保存模板。

字段绑定规则：

- 如果绑定字段有内容，刷新时会显示真实数据源内容。
- 如果绑定字段为空，刷新时该元素显示为空。
- 图片元素实际渲染优先使用数据源的商品图片。
- 条码和二维码建议绑定来源编号、参考值或自定义字段。

文字设置：

- 宽高自适应内容：适合短文本，元素会按内容自动调整。
- 固定宽高文字处理：适合固定区域，支持按宽度换行并裁剪，或不换行裁剪。
- 字体大小：建议根据标签尺寸控制，不要过大。
- 字重：常规或加粗。
- 对齐：左、居中、右。
- 文字颜色、背景颜色、边框颜色：从颜色面板选择。

图片设置：

- “图片预览地址”用于设计器预览。
- 实际刷新时，如果绑定数据源有商品图片，会优先使用商品图片。
- 图片会按标签渲染策略处理为标签可显示的颜色。

设计建议：

- 先选择正确屏幕规格和色彩模式，再开始布局。
- 三色标签重点使用黑、白、红，不建议使用过多灰阶。
- 价格、商品名等关键内容要留足空间。
- 文本较长时，使用固定宽高和换行裁剪。
- 发布前先保存并检查缩略图。

发布模板：

1. 在设计器点击“保存”保存草稿。
2. 点击“发布”。
3. 系统会保存当前画布，发布模板。
4. 如果有显示节点正在使用该模板，会创建标签刷新任务。
5. 到“任务中心”查看任务执行。

## 11. 绑定模板、商品和标签

一个标签能否刷新成功，取决于它是否有有效数据源和有效模板。

有效模板来源：

- 标签自身绑定的模板。
- 标签绑定的数据源设置的默认模板。

推荐绑定方式：

1. 数据源里选择默认模板。
2. 显示节点绑定到对应数据源。
3. 如果某些标签需要特殊版式，再单独给显示节点设置模板。

单标签绑定：

1. 进入“显示节点”。
2. 搜索标签码。
3. 点击“绑定”或“编辑”。
4. 选择数据源。
5. 可选选择模板。
6. 保存。

批量绑定：

1. 在“显示节点”勾选多个标签。
2. 点击“批量绑定”。
3. 选择数据源和模板。
4. 保存。

绑定后立即刷新：

- 单个标签可点击“刷新”。
- 数据源可点击“触发刷新”。
- 模板可点击“发布”并刷新绑定标签。

## 12. 下发刷新任务

系统会在以下场景创建刷新任务：

- 显示节点点击“刷新”。
- 商品/数据源点击“触发刷新”。
- 编辑数据源并保存后，系统刷新绑定标签。
- 模板发布后，系统刷新绑定模板的标签。
- 批量刷新接口触发指定数据源、模板或标签。

任务执行流程：

1. 创建任务。
2. 任务进入 queued 排队。
3. 系统确认标签所属基站。
4. 如果标签离线或未确认在线，系统尝试唤醒。
5. 渲染模板图片。
6. 通过 AP WebSocket 下发。
7. 等待基站或标签返回。
8. 成功则标记 success，失败则标记 failed 或 timeout。

任务状态说明：

- queued：任务已提交，正在排队。
- trigger_pending：等待触发，通常表示标签需要先被唤醒或等待基站扫描确认。
- rendering：正在渲染标签图片。
- sending：正在向基站下发。
- success：刷新成功。
- failed：刷新失败。
- timeout：等待返回超时。
- cancelled：任务取消。
- superseded：已有更新的刷新任务覆盖了这条任务。

任务中心操作：

- 查看：打开任务详情抽屉。
- 重试：手动重试失败或超时任务。
- 删除：删除任务记录，不删除标签、基站、商品或模板。

重试规则：

- 系统自动重试不增加页面上的手动重试次数。
- 用户点击“重试”才增加 Retries。
- 手动重试会在当前任务上执行，不需要重新创建一条完全独立的任务。
- 手动重试会先尝试激活/唤醒标签，再刷新数据。

大量任务建议：

- 一次批量刷新很多标签时，不要反复点击发布或刷新按钮。
- 如果误触发多次，系统会尽量用后面的刷新覆盖前面未执行的同标签任务。
- 任务列表分页返回，建议按 50 或 100 条查看。
- 基站刚上线时，等标签在线稳定后再批量刷新，成功率更高。

## 13. 查看任务详情和判断失败原因

在“任务中心”点击“查看”。

任务详情包含：

- 任务概况：任务类型、状态、创建时间、更新时间和重试次数。
- 关联信息：数据源、显示节点、AP 基站和模板。
- 当前进度：系统对任务结果的解释。
- 技术详情：下发方式、命令编号、追踪编号和原始说明。
- 基站返回记录：基站回包和执行事件。
- 本次生成的预览图：用于确认渲染图片是否正确。

常见失败原因：

- AP websocket is not connected：基站不在线或连接断开。
- no_online_ap：没有可用在线基站。
- no_template：标签没有可用模板。
- no_bound_devices：数据源或模板没有绑定标签。
- Waiting trigger：等待标签真实回复或等待周期性重试。
- timeout：任务已下发但长时间没有成功回包。
- 标签离线：基站未扫描到标签或标签不在范围内。

排查顺序：

1. 查看 AP 是否在线。
2. 查看标签是否属于该 AP。
3. 查看标签是否在线或最近被扫描。
4. 查看标签是否绑定数据源和模板。
5. 查看任务预览图是否生成。
6. 查看基站返回记录是否有错误。
7. 点击“唤醒”后再重试。

## 14. Dashboard 使用

仪表盘用于快速查看系统运行状态。

主要指标：

- AP 在线：当前在线基站数量。
- AP 离线：当前离线基站数量。
- 设备在线：当前在线显示节点数量。
- 今日成功任务：当天成功刷新的任务数量。

事件列表：

- 最近 AP 事件：基站上线、离线或状态更新。
- 最近失败任务：最近失败的刷新任务。

Dashboard 会定时刷新，不需要手动刷新浏览器。

## 15. AP 详情页使用

进入“AP 基站”，点击某个基站的“查看”。

AP 详情页包含：

- 基站概况：编码、状态、名称、位置、IP、MAC、固件版本、绑定设备数、自动发现设备数、最后在线和最后心跳。
- 当前配置：心跳、信道、发射功率、模块版本、网关等。
- 最近心跳：基站上报状态、等待队列、发送中数量和标签数量。
- 最近任务：该基站相关任务。
- 基站接入 / 下发日志：连接、扫描、下发相关记录。
- 已绑定商品设备：正式绑定商品或模板的标签。
- 自动发现设备：基站扫描到但不一定已业务绑定的标签。

常用操作：

- 同步状态：刷新当前基站状态。
- 编辑基站：修改名称、门店、IP、MAC、位置和配置。
- 解绑设备：解除该基站下所有显示节点与基站的绑定。
- 转移归属：管理员将基站和相关设备转移给其他账号。
- 刷新详情：手动刷新详情页数据。
- 删除基站：删除基站记录，但保留标签、商品和模板数据。

## 16. 常见问题排查

### 16.1 基站列表没有出现真实基站

检查：

- 门店号是否已创建。
- 基站配置里的服务器地址是否正确。
- 基站配置里的门店号、用户名、密码是否正确。
- 服务器 API 端口是否开放。
- 基站是否能访问服务器。
- 基站是否填写了公网 IP 或域名，而不是 `localhost`。

处理：

- 先在“门店管理”创建门店。
- 在“AP 基站”手动登记基站 MAC。
- 重启或重新保存基站网络配置。
- 查看 AP 详情日志或服务器日志。

### 16.2 基站在线，但标签没有入库

检查：

- 该基站是否开启“自动扫描入库”。
- 标签是否在基站通信范围内。
- 标签是否有电。
- 基站详情的“自动发现设备”是否出现该标签。
- 显示节点页面能否搜索到该标签码。

判断：

- 如果自动发现设备里有标签，但显示节点没有，说明入库逻辑异常或自动入库关闭。
- 如果自动发现设备也没有，说明当前系统没有收到该标签扫描上报。
- 如果官网能看到但本系统看不到，说明官网链路收到，本系统链路没有收到或没有保留该上报。

处理：

- 开启自动扫描入库。
- 将标签靠近基站等待下一轮扫描。
- 点击标签“唤醒”。
- 检查基站上报日志。

### 16.3 标签一会在线一会离线

可能原因：

- 基站刚上线，扫描结果尚未稳定。
- 标签数量多，基站需要较长时间轮询。
- 标签在通信边缘，信号弱。
- 基站正在处理大量刷新任务，扫描确认被延后。

处理：

- 等待 10 到 15 分钟观察稳定状态。
- 优先处理刷新任务，避免连续批量发布。
- 调整基站位置或增加基站覆盖。
- 对单个问题标签点击“唤醒”。

### 16.4 点击发布后任务很多，页面看起来一直在排队

说明：

- 发布模板会为绑定该模板的标签创建刷新任务。
- 标签多时任务会分页展示并排队执行。
- 每个基站有并发限制，避免把基站内部队列打满。

建议：

- 不要重复点击发布。
- 到“任务中心”查看任务分页。
- 使用搜索或按状态查看任务。
- 先确认基站在线和标签在线，再大批量刷新。

### 16.5 任务一直 Waiting trigger

含义：

- 系统正在等待标签真实回复。
- 标签可能离线，也可能暂时没被基站扫描到。
- 系统会按策略周期性尝试唤醒或重新下发。

处理：

- 确认标签在基站范围内。
- 点击标签“唤醒”。
- 检查 AP 是否在线。
- 如果长时间失败，点击任务“重试”。

### 16.6 标签上显示方框或文本没显示

可能原因：

- 模板绑定字段为空。
- 字体或渲染策略不支持某些字符。
- 文本元素尺寸太小，被裁剪。
- 色彩模式或屏幕规格选择错误。

处理：

- 确认数据源字段有值。
- 模板元素绑定正确字段。
- 增大文本框宽高，启用换行或自适应。
- 选择正确标签规格和色彩模式。
- 在任务详情查看生成的预览图。

### 16.7 商品字段改了但标签没变

检查：

- 商品是否绑定了显示节点。
- 显示节点是否有模板。
- 模板元素是否绑定了对应字段。
- 保存商品后是否创建刷新任务。
- 任务是否成功。

处理：

- 商品列表点击“触发刷新”。
- 显示节点列表点击单标签“刷新”。
- 任务失败时查看任务详情并重试。

## 17. 日常操作推荐流程

新增一批标签：

1. 确认门店和基站已创建。
2. 确认真实基站在线。
3. 打开 AP 的“自动扫描入库”。
4. 将标签放入覆盖范围。
5. 等待标签出现在“显示节点”列表。
6. 批量绑定数据源和模板。
7. 批量刷新或发布模板刷新。

新增一个商品并刷到标签：

1. 进入“商品管理”新增数据源。
2. 填写名称、来源编号、字段 1、字段 2等需要展示的字段。
3. 选择默认模板。
4. 保存。
5. 进入“显示节点”，将目标标签绑定到该数据源。
6. 点击标签“刷新”，或回到商品列表点击“触发刷新”。
7. 到“任务中心”查看结果。

修改模板并刷新所有绑定标签：

1. 进入“模板管理”。
2. 点击目标模板“设计”。
3. 修改元素、字段绑定和布局。
4. 点击“保存”。
5. 点击“发布”。
6. 系统为绑定该模板的标签创建任务。
7. 到“任务中心”查看任务执行。

更换标签绑定商品：

1. 进入“显示节点”。
2. 搜索标签码。
3. 点击“编辑”。
4. 修改数据源和模板。
5. 保存。
6. 点击“刷新”。

## 18. 现场实施检查清单

上线前检查：

- 服务器能被基站访问。
- API 端口开放。
- 门店已创建。
- 基站已登记或能自动登记。
- 基站配置里的门店号、用户名、密码正确。
- 基站在线并持续心跳。
- 自动扫描入库已按需要开启。
- 标签能在自动发现设备里看到。
- 显示节点列表能搜索到标签。
- 模板屏幕规格和色彩模式正确。
- 标签已绑定数据源和模板。
- 单标签刷新成功后，再进行批量刷新。

批量刷新前检查：

- 基站在线。
- 标签在线数量稳定。
- 任务中心没有大量历史任务卡住。
- 模板预览图正确。
- 数据源字段内容正确。
- 不要重复点击发布或刷新。

异常排查检查：

- AP 详情页查看最后心跳。
- AP 详情页查看自动发现设备。
- 显示节点列表搜索标签码。
- 任务中心查看失败任务。
- 任务详情查看预览图和基站返回记录。
- 必要时点击唤醒后重试。

## 19. 管理员数据权限建议

当前系统按账号归属隔离数据：

- 管理员可以看到非管理员账号的数据。
- 非管理员只能看到自己的数据。
- 管理员之间的数据也保持隔离。

建议实际组织方式：

- 总部账号使用 ADMIN。
- 区域或门店负责人使用 OPERATOR。
- 只读监控人员使用 VIEWER。
- 门店、基站、数据源、模板和标签尽量归属到实际负责账号。
- 如果要把某个基站和其标签交给其他账号，可在 AP 详情中使用“转移归属”。

更复杂的组织体系建议：

- 总部账号：查看全部门店数据，负责模板和账号管理。
- 区域账号：查看下属多个门店。
- 门店账号：只查看本门店。
- 只读账号：只能查看状态和任务，不允许修改。

如果未来需要总部/区域/门店三级权限，建议新增“组织”或“租户”模型，不只依赖单个 `ownerUserId` 字段。

## 20. 术语对照

- AP / Station / eStation：基站。
- ESL / Label / Display Node：电子价签 / 显示节点。
- Product / Data Source：商品 / 数据源。
- Template：模板。
- Publish：发布模板。
- Refresh：刷新标签。
- Wake：唤醒标签。
- Discovered Devices：自动发现设备，基站扫描到的标签。
- Bound Product Devices：已绑定商品设备，已经业务绑定的标签。
- Queue：排队。
- Retry：手动重试。
- WebSocket：基站和系统之间的主要连接通道。
- MQTT：消息桥接和观察通道，也可用于外部集成。
